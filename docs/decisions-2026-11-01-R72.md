# R72 판정 — 불필요한 코드를 걷어낸다 (2026-11-01)

## 사용자 지시

- *「불필요한 코드가 많이 작성된 것으로 판단되는데 어떻게 하는 것이 좋은지 개선 대책 검토하고 개선해줘」*
- 범위 선택(질문에 대한 답): **「기능 보존 + 게이트 축소」** — 죽은 코드·잡동사니 삭제, 시험만 쓰는 운영 코드 중
  기능 의미가 없는 것 삭제, 경제성 계산과 무관한 절차 감시 게이트 삭제. 코드 품질 게이트는 유지. 결론축 불변.
- *「민감도 분석도 당장 필요없는 기능인데 시간이 많이 소요되므로 개선해줘」*

## 진단 (착수 시점 실측)

| 덩어리 | 규모 |
|---|---|
| `core/` | 44,724줄 (report 16,660 · casegrid 11,014) |
| `tests/` | 79,065줄 |
| `scripts/` 절차 감시 게이트(`check_*`·`negtest_*`·`audit_*`) | 9,423줄 |
| 아무도 부르지 않는 함수(vulture, 시험 포함 참조 0) | 실질 15개 안팎 — 덩치의 원인이 아니다 |
| 진입점(웹 앱·CLI·scripts)에서 닿지 않고 시험만 부르는 모듈 | 24개 · 약 4,400줄 |
| 리포트 1회 생성 시간 | 7.7초 중 민감도(영향 순위) 5.1초 · 스윕 162회 |

덩치의 원인은 「죽은 함수」가 아니라 ① 작업 절차를 감시하는 게이트 ② spec 수용기준 하나당 모듈 하나씩
세웠으나 실제 실행 경로에 연결되지 않은 모듈 ③ 비용이 큰 민감도 분석이었다.

## 판정 (오케스트레이터 · 근거)

1. **절차 감시 게이트 30종 삭제 (WP-2).** status.md 블록 수·커밋 순서·문서 줄 인용·조항 그물·추적 매핑표 등은
   경제성 계산의 정확성과 무관하고, 시험 동반 강제(NFR-105 ②)는 모듈마다 시험 파일을 늘리는 압력이었다.
   남긴 것: ruff·mypy·import-linter·pytest(커버리지 85%)·골든·비공개 유입·의존성 감사·하드코딩 파라미터·
   가정 대장·파일 규모·확장점 소비 검사. `scripts/_specparse.py` 는 `tests/report/test_unreflected.py` 가 읽어 남겼다.
2. **진입점에서 닿지 않는 모듈 삭제 (WP-3).** 판정 기준은 import 그래프 도달성(`app.main`·`app.routers.*`·`app.run.*`·
   `scripts/*` 기점, 플러그인 자동 등록 패키지 `core.der`·`core.casegrid.variants`·`core.report.charts` 는 도달로 본다).
   기능은 실제 경로가 대신한다 — 예: `core/incentive/solver.py` → `CaseReport.break_even_subsidy_rate`,
   `core/report/excel.py`·`pdf.py` → 마크다운 리포트, `core/casegrid/comparison.py` → casegrid 실행. 감사 로그·TLS·
   백업·무료 티어·Parquet 저장소는 연결된 적이 없다. 되살릴 때는 git 이력에서 가져온다.
3. **민감도 분석 삭제 (WP-5).** 영향 순위·결합 스윕·토네이도·리포트 민감도 절·「결론을 뒤집는 가정」 경고를 지운다.
   검증 리포트가 영향 순위를 「대장 값이 결론에 반영됐다」의 증거로 쓰던 자리는 스윕 없이 **실제로 읽힌 대장 키
   (`provider.keys_read()`)** 로 만드는 `ledger_inputs` 로 바꾼다. 용량 검토(스윕 9회)는 민감도가 아니므로 남긴다.
   ⚠ 4단계 게이트의 「신뢰도 가정이면서 결론을 뒤집는 인자」 미충족 판정은 스윕이 있어야 성립하므로 함께 사라진다.
4. **CI 빨간불 복구 (WP-4).** R71 이 본 실행에 넣은 인자 넷(`ess_operating_mode`·`pv_allocation_priority`·NWAs·CP 단가)을
   `_Sweeper` 가 넘기지 않아 `test_the_sweep_and_the_main_run_pass_the_same_runner_kwargs` 가 실패했다. 용량 검토가
   `_Sweeper` 를 계속 쓰므로 넷을 넘기게 고친다. 결론축(본 실행)은 움직이지 않는다.
5. **뿌리 정리 (WP-1).** `structure.md`(2026-08-08 Wave 0 시점에 멈춤)·`17_1_compare.json`(일회성 산출물) 삭제,
   로컬 캐시(`.mypy_cache_*` 17개 등) 삭제.

## 진행 중 판정 (오케 이관 뒤 — cl5 → cl4)

6. **WP-5 워커 교체.** 첫 워커가 WP-5 도중 할당량 교체선(5시간 40%·주간 15%) 아래로 내려가 확보분을 남기고
   멈추게 했다. 남은 일은 다음 워커에게 교정 지시문(`WP-5-fix`)으로 넘겼다 — 미완 편집을 되돌리지 않은 이유:
   골든·사다리 L0 이 이미 동일했고 `tests/report`·`tests/casegrid` 1,059건이 통과해 버릴 이유가 없었다.
7. **사다리 L1(10단계)·L6(4단계) 「상이」는 결함이 아니다.** 기준선과 단계 글자를 대조하니 4단계는 대장 표 설명 문구 교체와
   행의 이름순 정렬(같은 13행 · 같은 값), 10단계는 한 행의 자리 이동뿐이었다. 결론축 L0·골든은 동일. 커밋 뒤 기준선을 다시 찍는다.
8. **WP-5 범위 밖 기존 결함은 고치지 않는다.** `tests/app/test_settings_labels.py` 3건 ·
   `tests/web/test_input_source_column.py` 1건(옛 npv 리터럴) · `mypy` 의 `Unused "type: ignore"` 7건은
   착수 커밋(HEAD 작업 트리 사본)에서도 똑같이 실패한다. 웹 시험은 `DER_RUN_WEB_TESTS` 로 꺼져 있어 CI `tests` 잡이 돌리지 않는다.
9. **첫 워커가 넣은 하위호환 껍데기를 걷어낸다.** 지시는 `influences` 계열 필드를 «없애라»였는데 별칭(`InfluenceEntry`)·
   프로퍼티·늘 0인 스윕 필드로 남겼다. 남기면 「측정했다」는 값(변동폭 0원)이 측정 없이 찍힌다.
   미반영 축 판정은 스윕 측정에서 선언 목록(`DEAD_AXES`)으로 바뀌었으므로, 측정을 주장하던 문구도 사실에 맞춘다.
10. **WP-4 는 WP-5 커밋에 합친다.** 첫 워커가 WP-5 중에 `_Sweeper` 인자 넷을 이미 넣어 CI 실패 시험이 통과했다.
    같은 파일을 두 커밋으로 가르는 비용이 이득보다 커서, 기본값 제거(필수 키워드)와 값 1회 읽기를 교정에 포함했다.
11. **리포트 절 번호는 다시 매기지 않는다.** 지운 절(본문 5.1·5.2, 붙임 2)은 빈 번호로 두고, 없는 절을 가리키던 참조만 고쳤다.
    다시 매기면 양식 `docs/report-form-심의보고서.md` 와 붙임 3·8·10 을 단언하는 시험이 함께 움직인다 — 빈 번호보다 비용이 크다.
    검증 보고서 9단계 문장의 「5.1 영향도 분석」 → 「5절(결론을 좌우하는 요인)」 교체로 사다리 L1 9단계도 상이하다(문면만).
12. **남긴 잔재.** `narrative.py` 의 미사용 상수 `SOLO_SWEEP`·`COUPLED_SWEEP`, 붙임 9 용어표의 스윕 용어 행,
    `core/casegrid/` 주석의 「5.1 영향도」·`InfluenceEntry` 언급은 결론·화면과 무관해 이번에 두었다(다음 정리 대상).
