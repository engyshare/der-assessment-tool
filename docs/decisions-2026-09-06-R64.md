## 1. `pyproject.toml` 의 `[tool.mypy] python_version` 을 고치는 것을 **승인했다**

### 사용자 문면
> 수정해줘 ; pyproject.toml 이 python_version = "3.11"

### 무엇이 문제였나 (오케스트레이터 실측 · 2026-09-06 착수 baseline)
저장소 `.venv` 는 **Python 3.13** 인데 `python_version = "3.11"` 이 박혀 있어,
`numpy 2.5.1` 스텁의 3.12 문법(`type` 문)에서 파서가 죽었다:

```
numpy/__init__.pyi:737: error: Type statement is only supported in Python 3.12 and greater  [syntax]
Found 1 error in 1 file (errors prevented further checking)
```

⇒ `rc=2` 로 끝나며 **`core` 를 한 파일도 검사하지 못한다.** 이 저장소가 반복해 잡아 온
「검사가 통과했다 ≠ 검사가 무언가를 검사했다」의 한 형태이고, `| tail` 로 읽으면
`rc` 가 `tail` 의 것(0)이 되어 **통과처럼 보인다.**

### 판정 — **줄을 지운다.** `"3.13"` 으로 올리지 않는다
비워 두면 mypy 가 **실행 중인 인터프리터** 버전으로 검사한다.

| 갈래 | 로컬(3.13) | CI(3.11) | 잃는 것 |
|---|---|---|---|
| `"3.11"` (종전) | **rc=2 · 0파일** | 초록불 | 로컬 mypy 전부 |
| `"3.13"` 으로 올린다 | rc=0 | 초록불 | ⚠ **3.11 지원 보장** — CI 는 3.11 로 시험을 돌리는데 mypy 만 3.12+ 문법을 허용해 구멍이 생긴다 |
| **줄을 지운다** (채택) | **rc=0 · 135파일** | **동작이 이전과 같다** | 없다 |

⚠ **§16.4 는 이 파일을 WP-15 단독 소유·append-only 로 못 박는다.** 이 편집은
**요청하고 승인을 받아** 한 예외이며, 다른 구획이 같은 이유로 스스로 고쳐도 된다는
뜻이 **아니다.** 사유는 그 파일 주석에 실측 로그와 함께 남겼다.
