> 사용자가 정한 것을 옮긴 것인데, 이 문서는 **오케스트레이터가 판단한 것**이다
> (2026-09-03 사용자 상시 판정: *「오케스트레이터가 합리적으로 판단하고, 끝난 뒤

## §1 무엇을 판정했나 — **③-2 지목 47건 중 인용 5건 이상인 12건**

`scripts/audit_clause_selfreference.py` 는 *「조항 X 의 인용이 1건 이상인데 어느
인용도 자기 문면에 X 를 적지 않고, 그런데 어떤 인용은 다른 조항 Y 를 적는다」*
는 자리를 **지목**한다. 지목은 판정이 아니다 — 독스트링은 거짓일 수 있다.

**대조를 손으로 하지 않았다.** 이 저장소는 전수 대조를 손으로 쓰게 했을 때
**조항 문면을 지어냈다.** 그래서 R59 는 순서를 뒤집었다:

> ① 도구를 세운다(`scripts/audit_clause_dossier.py`) → ② 도구가 **spec 원문에서**
> 조항 문면을 뽑아 인용과 나란히 낸다 → ③ 그 대장에서만 인용하며 판정한다

⚠ **대장은 `.orch/` 안이라 다른 기계에 없다.** 다시 만드는 명령:

```
python scripts/audit_clause_dossier.py --from-audit --min-citations 5 --out <경로>
```

도구가 빠뜨리지 않았음을 실측했다 — **대장에 빠진 인용 0건** ·
**원문과 다른 조항 문면 0건**(대장의 조항 문면 각 줄이 spec 그 줄의 부분
문자열인가를 대조).

기준선 실측(2026-09-04): **인용 있는 조항 302건 · 인용 1,489건 · 후보 47건** ·
최다 인용 `NFR-303-M1` **171건**. 인용 5건 이상 후보는 **12건**이다.

### ★ `NFR-303-M1` 이 메타 조항이라는 판단의 근거 — **대장에서 인용한다**

브리프가 조심하라고 한 자리다. 근거 셋 모두 대장 안에 있다.

- **조항이 규약 자체를 정한다.** 상위 `NFR-303` 문면이 *「어떤 필드가 / 왜 / 어떻게
  고쳐야 하는지」* 라는 **세 요소**를 정하고, `M1` 은 그 리뷰 체크리스트다. 저장소의
  모든 거부 검사가 그 셋을 단언하므로 온 저장소가 인용하는 것이 정상이다.
- **171건 중 165건은 다른 조항 ID 를 아예 적지 않는다**(대장 실측). ③-2 의 「다른
  조항을 적는다」 신호는 나머지 **5건**에서만 나오고, 그 5건이 적은 것은
  `FR-802-AC3`·`FR-801-AC4`·`FR-607-AC1`·`FR-402-AC2.A`·`FR-402-AC5`·`FR-105-AC5` —
  전부 **그 검사가 함께 재는 도메인 조항**이지 「NFR-303 대신 잰 것」이 아니다.
  예: #12(대장 `:2210`) 는 *「구조로 꺼내 `field`·`rule`·어긋난 길이(3, 2)가 사유에 있는지 단언한다」*
  라며 `DV-9` 의 세 요소를 재면서 동시에 `FR-802-AC3` 오라클을 짚는다.
- **저장소 스스로 경계를 적어 두었다.** `FR-401-AC2.AggregatedPPA` 의 인용 #7 이
  *「이 검사는 `NFR-303-M1` 을 재지 않는다 — `ValueError` 발생만 확인하고
  field·reason·action 3요소를 검사하지 않는다.」* 라고 적는다(대장 `:1145`).
  **「3요소를 단언하는 것」이 곧 `NFR-303-M1` 을 재는 것**이라는 뜻이며, 이 판정의
  기준을 저장소가 이미 그렇게 쓰고 있다.

### ★ `NFR-105-AC1` 을 「어긋났다」로 본 근거와 그 한계

조항 문면(대장 `:1646`)이 요구하는 것은 **순서**다 — *「구현보다 그 구현을 규정하는
실패 테스트가 **먼저** 존재해야 한다」*. 인용 24건이 재는 것은 **동반 여부와 커버리지**다.

⚠ **다만 마커를 옮겨 고칠 수 없다.** `NFR-105` 의 Measurement 1·2·3 은 spec 에
번호 목록(`1.` `2.` `3.`)으로 적혀 있어 `_specparse.CRITERION`(`- **M1** …`)에
걸리지 않는다. 실측:

```
NFR-105 ['NFR-105-AC1']
NFR-107 ['NFR-107-AC1.auto', 'NFR-107-AC1.manual', 'NFR-107-AC2', 'NFR-107-AC3',
         'NFR-107-AC4', 'NFR-107-AC5', 'NFR-107-M1']
```

즉 **`NFR-105-M1`·`M2` 라는 조항 ID 가 아예 없어서** 검사 24건이 갈 자리가 `AC1` 뿐이다.
그래서 이것은 「마커를 잘못 달았다」가 아니라 **spec 쪽 결손**이며, 고치는 것은
spec 개정(§16.5)이자 **다음 WP 의 오케스트레이터 판정 자리**다. 이 WP 에서는 고치지 않았다.

### ★ ③-2 지목의 **오탐 원천 둘** — 판정하며 드러났다

1. **합성 픽스처의 조항 ID 가 「적은 조항」으로 세어진다.** `NFR-107-M1` 의 인용
   16건 중 9건이 `FR-101-AC1` 을 적은 것으로 나오는데, 실물은 검사기에 먹일
   **합성 소스 문자열** 안이다 — `tests/ci/test_marker_substance.py:83` 의
   `"@pytest.mark.req('FR-101-AC1')\n"`. `_citations._mentions()` 가 함수 본문의
   문자열 상수를 보므로 픽스처 데이터가 주장으로 세어진다.
2. **약식 표기가 「자기 ID 를 안 적음」으로 세어진다.** `FR-1002-AC2`·`AC4` 의 인용
   #12/#20 독스트링은 *「13.1: 임계값 산출 및 여유폭 표시 (FR-1002-AC1, AC2, AC4).」*
   로 **자기 ID 를 실제로 적고 있다.** 정규식 `MENTION` 이 완전 ID 만 잡으므로
   `AC2`·`AC4` 는 안 걸리고 `FR-1002-AC1` 만 「다른 조항」으로 남는다.

두 가지 모두 **지목 도구를 고치라는 말이 아니다**(2절에 따라 손대지 않았다).
다음 라운드가 나머지 35건을 볼 때 같은 형태를 다시 만난다는 기록이다.


## §3 결론 — **열둘 중 하나가 어긋났고, 그것은 마커 문제가 아니라 spec 결손이다**

- **맞다 11건.** 자기 조항 ID 를 문면에 적지 않은 것은 **서술 습관**이며,
  지목 신호가 곧 결함이 아니라는 것을 열한 건이 실물로 보인다
- **어긋났다 1건 — `NFR-105-AC1`.** 조항이 요구하는 것은 **순서**다
  (*「구현보다 그 구현을 규정하는 실패 테스트가 **먼저** 존재해야 한다」*).
  인용 24건이 재는 것은 **변경분 커버리지와 테스트 동반**이다.
  **순서를 재는 인용은 24건 중 0건**이다
- **불명 0건**

### ★★ `NFR-105` 의 뿌리 — Measurement 셋이 **조항 ID 가 되지 못했다**

spec 의 `NFR-105` 는 Measurement 를 **번호 목록**(`1.` `2.` `3.`)으로 적는다.
바로 아래 `NFR-106` 은 같은 자리를 `- **M1** …` 로 적는다.
`scripts/_specparse.py` 의 `CRITERION` 은 후자만 잡으므로 **`NFR-105-M1`·`M2`·`M3`
라는 조항 ID 가 아예 없다.** 실측:

```
NFR-105 ['NFR-105-AC1']
NFR-107 ['NFR-107-AC1.auto', 'NFR-107-AC1.manual', 'NFR-107-AC2', 'NFR-107-AC3',
         'NFR-107-AC4', 'NFR-107-AC5', 'NFR-107-M1']
```

그리고 `NFR-105-AC1` 의 문면은 **요구사항 문장의 글자 그대로 복사본**이다.
⇒ 검사 24건이 갈 자리가 `AC1` 뿐이었고, **재는 것과 적는 것이 어긋난 채로
게이트가 초록불**이었다. 이것이 이 저장소가 반복해 밟은 형태다 —
*「검사가 있고 통과하는데 조항과 다른 것을 재고 있다」*.

## §4 ③-2 지목의 **오탐 원천 둘** — 나머지 35건을 볼 때 다시 만난다

1. **합성 픽스처의 조항 ID 가 「적은 조항」으로 세어진다.** `NFR-107-M1` 인용
   16건 중 9건이 `FR-101-AC1` 을 적은 것으로 나오는데, 실물은 검사기에 먹일
   **합성 소스 문자열** 안이다(`tests/ci/test_marker_substance.py`).
   `_citations._mentions()` 가 함수 본문의 문자열 상수를 보므로 **픽스처 데이터가
   주장으로 세어진다**
2. **약식 표기가 「자기 ID 를 안 적음」으로 세어진다.** *「(FR-1002-AC1, AC2, AC4)」*
   처럼 적으면 정규식이 완전 ID 만 잡아 `AC2`·`AC4` 는 안 걸린다

⚠ **지목 도구를 고치라는 말이 아니다.** 오탐을 줄이려고 신호를 좁히면 진짜를
놓친다 — `audit_` 가 차단이 아닌 이유와 같은 판단이다. **기록으로 남긴다.**

## §5 ③-2 지목의 **나머지** — 인용 4건 이하 **37건 전건**을 판정한다

### ★ 기준선이 R59 **안에서** 바뀌었다 — 47건이 아니라 48건이다

WP-3+4 가 `NFR-105` 의 Measurement 셋을 조항 ID 로 세우면서(spec v0.28) 지목이
움직였다. WP-5 가 직접 돌린 머리줄:

```

```

§1 의 기준선(302 · 1,489 · 47)과 다르다. 후보에서 **`NFR-105-AC1` 이 빠지고**
— §2 가 「어긋났다」로 판정한 그 조항이며, 검사가 `M1`·`M2`·`M3` 로 갈라져
가면서 더 이상 지목되지 않는다 — **`NFR-105-M1`·`NFR-105-M3` 둘이 새로 들어왔다.**

§2 가 판정한 12건 중 **11건이 아직 후보다**(`NFR-105-AC1` 만 빠졌다).
남은 것은 **48 − 11 = 37건**이고, 이 절이 그 **37건 전부**를 판정한다.
브리프가 적은 「35건」은 마커가 옮겨지기 전의 수다.

대장을 다시 만드는 명령(대장은 `.orch/` 안이라 다른 기계에 없다):

### §5.2 합계

**맞다 33 · 어긋났다 4 · 불명 0 · 판정하지 못한 것 0.**
③-2 지목 48건은 이로써 **전건이 판정되었다**(§2 의 11건 + 이 절의 37건, 그리고
§2 가 판정한 `NFR-105-AC1` 은 마커가 옮겨져 후보에서 빠졌다).

「맞다」33건 중 **오탐 원천으로 설명되는 것이 11건**이다 — 약식 표기(②) 7건
(`FR-1001-AC4`·`FR-103-AC1`·`FR-105-AC2`·`FR-106-AC4`·`FR-604-AC8`·`FR-609-AC3`·
`FR-905-AC5`), 합성 픽스처(①) 4건(`NFR-107-AC1.auto`·`NFR-107-AC1.manual`·
`NFR-107-AC3`·`NFR-107-AC5`). 나머지는 **자기 ID 를 안 적은 서술 습관**이며,
적힌 「다른 조항」은 그 단언이 **함께 재는** 조항이다.

### §5.3 어긋난 넷 — 다음 라운드가 집을 자리

#### ⚠ `FR-604` 는 낱건이 아니라 **마커가 한 칸씩 밀렸다**

두 건(`AC5`·`AC6`)이 ③-2 에 걸렸지만, 형제 조항을 대장으로 펴 보면 **다섯
조항이 같은 방향으로 밀려 있다.** 밀린 것 중 셋은 **자기(틀린) ID 를 문면에
적고 있어서** ③-2 그물에 애초에 걸리지 않는다.

| 조항 | 조항 문면 (대장) | 그 조항의 인용이 실제로 재는 것 | 걸렸나 |
|---|---|---|---|
| `FR-604-AC2` | *「보조: 보조율(%) 또는 정액(원), 상한, 대상 비용 범위」* (`f:23`) | 융자 조건 — `loan_rate` · `loan_interest` · `loan_grace_years` · `loan_repayment_type` (`f:27`) | 아니오 |
| `FR-604-AC3` | *「융자: 융자율(%), 연이자율, 거치기간(년), 상환기간(년), 상환방식」* (`f:47`) | 세제 — `assert scheme.tax_credit_rate == 0.1` (`f:51`) | 아니오 |
| `FR-604-AC4` | *「자부담: 잔여 비율 자동 계산」* (`s:162`) | 지원 주체 — `assert scheme.sponsor == "지방비"` (`s:166`) | 아니오 |
| `FR-604-AC5` | *「세제: 세액공제율, 감가상각 방식·내용연수」* (`:2204`) | 지원 주체 — 같은 단언 (`:2208`) | **예** |
| `FR-604-AC6` | *「지원 주체: 국비 / 지방비 / 민간」* (`:2224`) | 보조 형태 — `subsidy_rate` · `subsidy_limit` · `subsidy_fixed` (`:2228`) | **예** |

- **무엇을 재고 있나** — 시험 넷(`보조 형태`·`융자`·`세제`·`지원 주체`)은
  전부 실재하고 각각 옳은 것을 잰다. **틀린 것은 어느 시험이 어느 조항의
  것인가**뿐이다.
- **무엇을 재야 하나** — `보조 형태 → AC2` · `융자 → AC3` · `자부담 → AC4`(현재
  **재는 시험이 없다**) · `세제 → AC5` · `지원 주체 → AC6`.
- **고치는 데 무엇이 필요한가** — `tests/incentive/test_incentive.py` 의
  `@pytest.mark.req` 마커를 한 칸씩 되돌리고 독스트링의 조항 번호를 함께 고친다.
  ⚠ 그러면 **`AC4`(자부담: 잔여 비율 자동 계산)를 재는 인용이 0건**이 되어
  `NFR-107` 미매핑이 뜬다. 시험을 새로 써야 하므로 **마커만 옮기는 일이 아니다.**

#### `FR-103-AC2` — 「독립적인 `IncentiveScheme` 참조」를 재는 인용이 0건이다

- **재고 있는 것**: 인스턴스별 재무 속성 차이(수명·단가·CAPEX·O&M·잔존가치).
  이 중 셋(`resources == 2`·`PV#1`·`PV#2`)은 `AC1` 문면 그대로다.
- **재야 하는 것**: 두 인스턴스가 **서로 다른 `IncentiveScheme` 을 참조**한다는
  것. 한 시험이 `AC1`·`AC2`·`AC3` 세 마커를 함께 달고 있는데 `AC2` 몫이 없다.
- **필요한 것**: 시험 신설. 마커를 떼기만 하면 `AC2` 가 미매핑이 된다.
  ⚠ 같은 시험이 단 `AC3`(*「두 인스턴스의 현금흐름이 프로포마에서 **분리된
  행**으로 표시된다」* `s:27`)도 프로포마 행을 단언하지 않는다 — `AC3` 은 자기
  ID 를 적어서 ③-2 에 걸리지 않았다(`s:31`).

#### `FR-204-AC2` — Phase 2 조항에 Phase 1 시험이 달렸다

- **재고 있는 것**: 에너지자립가구 2변형 템플릿 = `AC1` 문면.
- **재야 하는 것**: *「마을단위 분산특구 6개 모델, 아파트 마이크로그리드 모델」*.
- **필요한 것**: 조항 자신이 **`[Phase 2]`** 로 적는다. 지금 재는 것이 없는 것이
  옳고, 잘못은 **Phase 1 시험에 이 마커를 단 것**이다. 마커를 떼면 `AC2` 는
  미매핑이 되는데, `NFR-107` 은 **Must-have** 를 대상으로 하므로 Phase 2 항목이
  미매핑인 것이 정상인지부터 정해야 한다 — **오케스트레이터 판정 자리다.**

#### ★ 넷 모두 **고치지 않았다**

2절 판정대로 이 WP 는 **판정만** 한다. 마커·조항·시험·소스를 한 건도 바꾸지
않았다. §2 가 찾은 어긋남 하나를 고치는 데 WP 둘이 들었다 — 위 넷은 **시험
신설이 따라오므로 그보다 크다.**
