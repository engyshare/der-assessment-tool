## 2. `MC-3` — 모든 입력 필드가 **단위·설명·기본값 출처**를 툴팁으로

종전에는 배지 2건이 `web/render.py::demo_context()` 의 데모 값인데도 화면이 그것을

```
데모 값 — 실제 결과가 아니다

```

⇒ ★ **`MC-6` 의 모집단 판정이 달라진다.** 종전에는 사람이 「이게 데모인지」를
코드를 열어야 알았다. 지금은 화면 글자가 **배지 2건을 「전 항목」의 모집단에서
빼라고 스스로 말한다.** 그것을 받아들일지가 판정이다.

| 볼 것 | 사람이 적는 칸 |
|---|---|
| 배지가 노랗고 눈에 띄는가 | |
| **표지를 받아들여 데모 2건을 모집단에서 뺄 것인가** — 빼면 「전 항목」이 0건이 된다 | |

## 8. 수행하고 나면 — 어디에 무엇을 적나

`docs/manual-checks.yaml` 의 해당 항목에 아래 칸을 채운다.

```yaml
    status: "수행"            # 미수행 / 수행 / 재수행필요
    verdict: "통과"           # 통과 / 미달 / 부분
    performed_at: "2026-__-__"
    performed_by: "____"
    sample: >-
      ____
    result_note: >-
      ____
    evidence: "docs/evidence/____"
```

⚠ **기록 없이 `status` 만 올리지 마라** — 이 대장의 기록 규칙(`NFR-107-AC3`)이
수행 일자·수행자·표본·결과를 함께 요구하고, 그중 하나라도 없으면 미수행으로 본다.

⚠ **부분 통과는 「부분」이라 적는다.** 특히 `MC-8` 은 앞 절반(axe)과 뒤 절반
(키보드)이 갈리므로 `result_note` 에 **둘을 따로** 적는다.
