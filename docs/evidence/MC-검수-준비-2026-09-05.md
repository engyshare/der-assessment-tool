## 2. `MC-3` — 모든 입력 필드가 **단위·설명·기본값 출처**를 툴팁으로

| 2 | `Tab` 로 「시나리오」 셀렉트까지 | 초점이 눈에 보이는가 (실측: 정지점 **7번째**) | |
| 3 | `↑`/`↓` 또는 글자 입력 | 시나리오를 고를 수 있다 | |
| 4 | `Tab` → `↑`/`↓` | 기준선 갈래 라디오 넷 사이를 옮긴다 (라디오군은 `Tab` 한 번에 하나로 센다) | |
| 5 | `Tab` → `Space` | 계측 전제 체크박스 둘을 켠다 | |
| 6 | `Tab` → `Enter` | 「분석 실행」이 눌리고 ④ 로 간다 | |
| 7 | ④ 에서 `Tab` | 「대시보드」 링크로 돌아갈 수 있다 | |
| 8 | 갈래를 바꿔 3~6 반복 | 수(`순현재가치`)가 **달라진다** | |
| 9 | 「자가용 집합자원화」를 전제 없이 6 | 거부 화면이 나오고 `필드`·`사유`·`조치` 를 읽을 수 있다 | |

세션 실측 참고: ① 에서 `Tab` 만으로 도는 정지점은 **103개**이고 마지막에 처음으로
되돌아온다 — **마우스 없이 닿지 못하는 조작은 ① 안에 없다.**

### 7-4. ⚠ 어느 후보로 정하든 사람이 봐야 하는 자리 셋

| 무엇 | 실측 | 사람이 적는 칸 |
|---|---|---|
| **「내보내기」 조작이 화면에 없다** | `grep -rn "내보내기" web/templates/` → **마법사 목록의 글자 한 줄뿐**. 리포트로 가는 링크가 ①·④ 어디에도 없다 | |
| **「마법사」는 눌러 넘길 것이 없다** | 「다음 단계」는 `type="button"` 이고 템플릿 넷에 `<script>` 가 **0개**다 — 눌러도 아무 일이 없다 | |
| **②·③ 으로 가는 링크가 없다** | ① 의 내비 다섯은 전부 `#` 앵커다. 주소를 쳐야 간다 = 키보드 완주 경로에서 끊긴다 | |

## 8. 수행하고 나면 — 어디에 무엇을 적나

`docs/manual-checks.yaml` 의 해당 항목에 아래 칸을 채운다.

```yaml
    status: "수행"            # 미수행 / 수행 / 재수행필요
    verdict: "통과"           # 통과 / 미달 / 부분
    performed_at: "2026-__-__"
    performed_by: "____"
    sample: >-
      ____
    result_note: >-
      ____
    evidence: "docs/evidence/____"
```

⚠ **기록 없이 `status` 만 올리지 마라** — 이 대장의 기록 규칙(`NFR-107-AC3`)이
수행 일자·수행자·표본·결과를 함께 요구하고, 그중 하나라도 없으면 미수행으로 본다.

⚠ **부분 통과는 「부분」이라 적는다.** 특히 `MC-8` 은 앞 절반(axe)과 뒤 절반
(키보드)이 갈리므로 `result_note` 에 **둘을 따로** 적는다.
