## Wave 게이트

Wave는 통합 순서이므로, 각 Wave 종료 시 **실물끼리 붙는지**를 확인한다.

| Wave | 종료 조건 |
|---|---|
| **0** | 임의 구획 담당자가 다른 구획 코드 없이 계약 스텁만으로 자기 테스트를 작성·실행할 수 있다. 실증 — PV 1종을 계약만 보고 구현하여 계약 테스트 통과 |
| **1** | 자원 6종 + 공통설비가 §13.2 검증 케이스 전건 통과. 전제·제도 계층이 실물 값으로 요금을 산출 |
| **2** | **단일 케이스 종단 실행 1회 성립** — 자원 → 엔진 → 편익 → CBA를 **그리드·UI 없이 CLI로** 한 번 통과시킨다 |
| **3** | 27케이스 그리드 실행 + 필요 지원 역산 + 영향도 리포트가 CLI로 산출된다 |

# 하위 작업

## 작성 규칙

- **TDD 순서** — `테스트 작성 → 실패 확인(RED) → 최소 구현(GREEN) → 정리`. 표기 `[T]` 테스트 · `[I]` 구현 · `[R]` 정리·문서

  **적용 범위**: NFR-105는 *"모든 **계산 코드**"* 에 걸린다. 계산 결과를 낳는 구획(4.0~13.0)에서는 **`[I]`가 첫 `[T]`보다 앞설 수 없다.**

  **예외 2건** — 2.0(저장소·CI)과 15.0(웹 UI)은 계산 코드가 아니므로 스캐폴딩 `[I]`가 먼저 온다. 다만 **동작 검증 테스트는 여전히 필수**이며, 두 작업 모두 뒤에 `[T]` 항목을 갖는다. 예외를 "테스트를 안 써도 된다"로 읽으면 안 된다 — 순서만 다르다.
- **수용기준 추적** — 하위 작업마다 대응 수용기준 ID를 명시한다. 테스트에 `@pytest.mark.req("FR-104-AC3")`으로 부착하면 `docs/traceability.md`에 자동 반영된다 (NFR-107)
- **크기** — 하위 작업 1건은 30분~2시간. 넘으면 쪼갠다
- **하위 작업의 정의 (건수를 세는 규칙)** — **`## N.0` 절 안의 최상위 목록 항목
  `- **N.M** …` 하나가 하위 작업 1건이다.** 들여쓴 `- 수용기준: …` 줄, 인용문(`>`),
  표는 세지 않는다. `### 6.0.S` 의 공통 5단계는 **템플릿이므로 문서에 적힌 그대로
  한 번만** 센다(6.1~6.6 에 반복 적용되지만 6배로 세지 않는다).

  **머리말·본문에 건수를 적을 때는 이 명령을 돌려 그 출력을 적는다.** 세지 않고

> ② **표식은 상속되지 않아야 한다.** `getattr` 로 보자 CEMS·HEMS·공용 계량통신 **셋 전부가** 등록에서 빠졌다. 그 상태는 「공통설비가 없는 단지」로 계산되고 CEMS 구축비·운영비가 통째로 사라지는데 결과는 그럴듯하다. `cls.__dict__` 로 고치고 검증 케이스로 고정했다.

> ③ **참조 구현이 레지스트리를 오염시킬 수 있었다.** `tests/contract/test_smoke_wave0.py` 의 `ReferencePV` 는 `tag = "PV"` 이므로, `__module__` 로 걸러내지 않으면 pytest 실행 중 스캔에서 진짜 `PV` 와 「등록 충돌」이 뜬다. 구현에 아무 잘못이 없는데도 뜨는 오류이고, 피하려고 참조 구현의 `tag` 를 바꾸면 그것은 계약 위반이다.

> **M1을 기계 검사로 바꿨다.** *"신규 자원 추가 PR의 diff에 공유 파일 변경 0줄"* 은 PR을 봐야 아는 사실처럼 보이지만, 그 diff가 필요해지는 **원인**은 소스에 있다 — 공유 파일이 자원 이름을 들고 있으면 추가할 때 고쳐야 한다. 그래서 「공유 파일의 **코드**에 자원 이름 0건」 + 「파일 하나를 더 놓으면 실제로 레지스트리가 는다」를 함께 본다. **둘 중 하나만으로는 부족하다** — 이름이 없어도 발견기가 고정 목록을 들고 있으면 늘지 않는다.
>
> **그리고 여섯 번째로 같은 함정에 걸렸다.** 공유 파일 검사를 문자열 포함으로 쓰자 **그 검사를 설명하는 주석과 독스트링이 그대로 걸렸다.** 해법도 같다 — `ast` 로 코드 식별자·문자열 리터럴만 뽑아 **서술과 선언을 가른다.** 심어 둔 등록부를 실제로 잡는지, 서술만 있는 파일을 오판하지 않는지 둘 다 검사한다(§13.0.1 ④) — 제외 범위를 넓게 잡으면 코드도 함께 빠져 진짜 등록부가 있어도 초록불이 된다.

## 2.7(매핑 게이트 활성화) 전 처리 — 인용 정합

> **v1.0 초판에서 수용기준 인용 7건이 다른 조항을 가리켰다.** ID가 실재하므로 `gen_traceability.py`는 잡지 못했다. 그 상태로 `@pytest.mark.req("FR-601-AC3")`을 붙이면 **엉뚱한 조항이 초록불이 되고 맞는 조항은 미매핑으로 남는다** — NFR-107이 막으려던 바로 그 상태다.
>
> 원인은 spec v0.7에서 34건 우선순위를 부여하며 AC가 중간에 삽입되어 이후 번호가 밀린 것이다. **개정 때마다 재발한다.**

**조치**: `scripts/check_task_mapping.py` 신설. 기계가 확실히 판정할 수 있는 것만 검사한다.

| 검사 | 잡는 것 |
|---|---|
| 범위 초과 인용 | AC가 5개뿐인 요구사항에 1~6 범위를 인용한 경우 (v1.0에서 FR-1101에 실제로 발생) |
| **미인용 Must-have 조항** | 인용이 엉뚱한 곳으로 갔을 때 **비어 버린 자리**가 드러난다 |
| 상위 작업 간 중복 인용 | 오귀속 의심 (정당할 수도 있다) |

> **인용은 `- 수용기준:` 필드에서만 수집한다.** 들여쓴 줄이면 무엇이든 세면 **조항을 언급하는 서술**과 **그 조항을 검증하겠다는 선언**이 구분되지 않는다. 실제로 아래 「부수 영향」 서술이 2.0의 인용으로 집계되어 유령 중복 5건을 만들었다.

> **어휘 유사도는 쓰지 않는다.** 시도했으나 한국어 조사·복합어 때문에 올바른 매핑도 0.00으로 나와 오탐 100%였다. 사람이 읽지 않게 되는 도구는 없느니만 못하다.

**현재 상태 (08-08)**: 범위 초과 0건 / **미인용 Must-have 0건** / 실재하지 않는 인용 0건 / 중복 인용 11건(전건 정당 — 계약 정의와 구현이 같은 조항을 가리키는 쌍). **종료 코드 0.**

> **미인용이 초판 64 → 22 → 28 → 23 → 5로 내려왔다.** 중간에 늘어난 구간(22 → 28)은 도구가 나빠진 것이 아니라 **정확해진 것**이다. 이전에는 서술 문장 속 조항 언급이 "인용됨"으로 세어져 6건을 가리고 있었다. 유령 중복과 같은 원인, 반대 방향의 오류다.

08-08에 23건을 spec 원문과 전수 대조하여 세 갈래로 판정했다.

| 갈래 | 건수 | 조치 |
|---|---|---|
| 작업은 있고 `- 수용기준:` 필드만 비어 있던 것 | **17** | 인용 보강 완료 (2.3·3.1·8.4·8.5·10.2·10.7·11.2·13.2) |
| 범위 누락 — 담당 작업이 없던 것 | **1** | 13.9 신설 (`FR-1003-AC2` PDF 심의자료) |
| **Phase 2 범위** — 이 목록에 없는 것이 정상 | **5** | 조치 없음. `FR-202-AC1`~`AC4`, `FR-204-AC2` |

> **Phase 2 범위 5건 중 4건은 2.15 ② 적용으로 자동 해소됐다.** `check_task_mapping.py`는 처음부터 `Must-have and Phase in ("1","-")` 로 걸러 왔다. 그런데 **Phase가 43건 공란이라 `"-"` 예외 통로로 전부 새어 들어오고 있었다.** 부록 A.1을 읽어 Phase를 채우자 필터가 비로소 작동해 `FR-202-AC1`~`AC4`가 빠졌다.
>
> 공란은 "정보 없음"이 아니라 **검사 우회**였다. 2.15 ③이 「Phase 미지정」을 요약에 집계하는 이유가 이것이다 — 드러나지 않는 공란은 게이트를 조용히 무력화한다.
>
> **마지막 1건 `FR-204-AC2`도 08-08에 해소했다 — 수용기준 단위 Phase 도입.** FR-204 자체는 Phase 1이 맞고(에너지자립가구 템플릿), 그 안의 AC2만 마을단위·아파트 모델이라 Phase 2였다. 필터가 요구사항 단위로만 동작해 걸러지지 않던 것이다.
>
> 조항 줄 끝에 **`[Phase N]`** 을 적으면 그 조항만 다른 Phase를 갖는다. 표기가 없으면 요구사항 Phase를 물려받는다. **본문에서 `Phase N`을 찾지 않는 이유**는 산문에 우연히 등장하면 오탐이기 때문이다 — 서술과 선언을 뜻으로 가르려는 시도는 이 저장소에서 네 번 실패했고, 판정 기준은 형식뿐이어야 한다. 위치를 줄 끝으로 고정해 우연한 일치를 배제했다.
>
> 이로써 **2.7의 선행 조건 넷이 전부 충족됐다.** 남은 것은 2.15 ① 하나뿐이며, 그것이 표 조항 수십 개를 새로 만들어 미인용을 다시 늘릴 것이므로 **2.7은 ① 완료 후에 켠다.**

**게이트를 먼저 켜면 안 된다** — 인용이 어긋난 채 초록불이 되는 것이 지금 막으려는 문제다.

```
python scripts/check_task_mapping.py            # 검사 3종
python scripts/check_task_mapping.py --review   # 인용 쌍 전건 대조
python scripts/check_task_mapping.py --fr FR-601  # 특정 요구사항 AC 목록
```
