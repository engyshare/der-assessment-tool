# DER Evaluator

분산자원(Distributed Energy Resources)으로 구성된 사업모델의 **경제성을 평가하는 오픈소스 도구**입니다. 태양광·ESS·V2G·히트펌프 등을 조합한 모델을 정의하고, 8760시간 운전을 시뮬레이션하여 NPV·IRR·회수기간과 **성립에 필요한 지원 수준**을 산출합니다.

> **상태: 설계 단계.** 요구사항 명세와 작업 목록은 완성되었고, 구현은 시작 전입니다.
> 저장소 구조는 [`structure.md`](structure.md), 진행 상황은 [`status.md`](status.md)를 보십시오.

## 왜 만드는가

스프레드시트 모형은 단건 검토에는 충분하지만 세 가지를 구조적으로 못 합니다.

1. **모델 다양성** — 자원 구성이 바뀌면 에너지 수지 계산 로직 자체가 달라져 시트를 새로 짜야 하고, 그 순간 모델 간 비교가 불가능해집니다.
2. **조합 탐색** — "설비단가 3수준 × 요금 3수준 × 이용률 3수준 × 할인율 3수준 = 81개 조합"을 자동 실행할 수 없습니다. 결과적으로 *"어떤 조건에서 이 사업이 성립하는가"* 에 답하지 못하고 단일 케이스 답변만 가능합니다.
3. **가정 추적** — 셀 수식은 재현되지만 **왜 그 값을 썼는지**(출처·기준연도·신뢰도)는 남지 않습니다.

이 도구는 스프레드시트를 대체하는 것이 목적이 아니라 위 세 가지를 담당합니다. 단건 정밀 검산은 엑셀 내보내기로 계속 지원합니다.

## 설계 원칙

- **자원은 플러그인** — 모든 분산자원이 공통 `DER` 인터페이스를 구현합니다. 신규 자원 추가 시 코어 엔진 수정 0줄이 요구사항이자 CI 검사 항목입니다.
- **테스트 우선(TDD)** — 산출물이 투자·정책 판단의 근거이고 **계산 오류는 화면상 정상으로 보이므로**, 수용기준을 먼저 테스트로 고정합니다.
- **가정은 데이터** — 모든 입력값이 출처·기준연도·신뢰도 등 부기 항목 7종을 보유하며, 신뢰도가 낮은 값은 영향도와 함께 보고됩니다.
- **편익 중복 계상 금지** — 동일 물리 현상을 두 항목으로 세지 않도록 배타 규칙을 선언적 테이블로 관리합니다.
- **요구사항 ↔ 검증 추적** — 모든 Must-have 수용기준이 최소 1개의 검증 항목에 매핑되어야 하며, 매핑표는 자동 생성됩니다.

## 검사 실행

```bash
pip install pyyaml

python scripts/check_source_rules.py     # 규칙 문서 판본 대조
python scripts/gen_traceability.py       # 매핑표 생성 + 미매핑 검사
python scripts/check_task_mapping.py     # 작업 목록 인용 검사
```

`check_source_rules.py`는 규칙 문서의 원본이 저장소 밖(로컬 노트)에 있을 때 `DER_VAULT_ROOT` 환경변수 또는 `--vault`로 그 위치를 받습니다. 지정하지 않으면 저장소 사본으로 대조하며, 사본은 원본과 바이트 동일해야 합니다.

## 협업 구조

명세 §16이 저장소를 **소유 경로가 겹치지 않는 구획(WP-0~WP-16)** 으로 나누고, 통합 순서를 Wave 0~4로 정의합니다. 작업 목록의 상위 17건이 각각 하나의 구획에 대응하므로, 여러 사람 또는 에이전트가 동시에 착수할 수 있습니다.

- 구획 밖 파일은 건드리지 않습니다. 공유 파일은 명세 §16.4에 전량 열거되어 있습니다.
- 작업 항목마다 대응 수용기준 ID가 명시되어 있습니다. 테스트에 `@pytest.mark.req("FR-104-AC3")`을 붙이면 매핑표에 자동 반영됩니다.
